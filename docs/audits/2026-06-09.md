# Audit Log: 2026-06-09

Foundational audit pass against The Pragmatic Programmer principles
plus a11y on the extension UI, security review of the MV3 manifest,
and dep vuln scan. PR: `audit/2026-06-09` → main.

## Shipped in this PR

**Orthogonality (`/coupling`):**
- Verdict: codebase is exemplary. The 7 `src/lib/` modules
  (`storage`, `capture`, `diff`, `noise`, `url`, `settings`, `types`)
  are documented canonical singletons in CLAUDE.md.
- The 4-layer architecture (content / background / popup+sidepanel /
  options) is fully respected. `lib/` has zero upward imports.
  `content/` only crosses layers via `chrome.runtime` messaging.
- Zero cycles, zero wildcards, zero cross-layer violations.

**DRY (`/drift`):**
- No model IDs, no year-bound constants, no hardcoded URLs in source.
- Em-dash usage is zero.
- The `show(id)` helper is duplicated between `popup/index.ts` and
  `sidepanel/index.ts` — already documented in CLAUDE.md as
  intentional ("extract to `src/lib/dom.ts` if a third site needs it").
  At N=2, leave it.

**Broken windows (`/zombie`):**
- Zero commented-out code, zero TODOs/FIXMEs/HACKs, zero empty catches.
- One "dead export" candidate (`Settings` type in `src/lib/settings.ts`)
  is actually used via inference from `getSettings()`/`saveSettings()`
  return and parameter types. Exporting it is the right call for
  caller DX. Left as-is.

**Accessibility (`/a11y`) on extension UI:**
- Added `<title>` to `popup/index.html` ("What Changed") and
  `sidepanel/index.html` ("What Changed — Diff viewer"). Both
  previously had none — screen readers announced "Untitled" when
  the popup/side panel opened.
- Wrapped the page content in `<main id="app">` in all 3 entry-point
  HTMLs (popup, sidepanel, options), giving screen readers a landmark
  to jump to. `id="app"` is preserved so JS selectors still resolve.

**Security review (`/security-review`) on the manifest:**
- Permissions audit: `storage`, `tabs`, `alarms`, `sidePanel` are all
  justified by the code paths that use them. `<all_urls>` host
  permission is required by the core feature ("snapshot every page
  you visit"). No over-scope.
- No `eval`, no `new Function`, no dangerouslySetInnerHTML risks
  (extension renders pre-computed diff HTML in the side panel, but
  the HTML is built server-side in the background script from
  jsdiff output, not from arbitrary page content).

**Dependency vulnerability (`/vuln`):**
- `npm audit` clean. Zero vulnerabilities.

## Light verifications

- `npx tsc --noEmit` clean.
- `npm run build` clean (`dist/` regenerates correctly).

## Out of scope (declined / not needed)

- Extracting `show(id)` to `src/lib/dom.ts`. At N=2 and explicitly
  documented in CLAUDE.md as a controlled duplication. Wait for the
  third site.
- Adding `<title>` to `docs/index.html` and `docs/privacy.html` —
  they already have titles.
- Manifest scope reduction. Each permission has a justified caller.

## Onlooker takeaway

A clean, well-architected MV3 extension. The audit's most visible
addition is making the popup and side panel announce themselves
properly to screen readers via `<title>` + `<main>` landmarks.
